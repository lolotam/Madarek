## Executed

One `AudioProvider` still owns the single `audio[data-audio-engine]` element. Manual segment changes go through an internal `moveTo(index, intent)` operation. `previous`, `next`, and `replaySegment` capture the current transport intent from `statusRef` / `desiredIntentRef` and keep that intent after the source swap. `restart()` still restarts the whole queue and plays. Natural `ended` auto-advance still uses `advance()` and the existing repeat modes.

Paused previous no longer restarts the current clip after 1.5s. It selects the previous narration segment at time 0 and stays paused until إكمال/resume. The same paused preservation applies to replay and next. Previous is disabled on the first segment; next is disabled on the last for manual navigation only.

A floating dock is another view of the same provider state: fixed on the visual right on desktop (`inset-inline-start` under `dir="rtl"`), compact bottom-right on small screens, with lesson-body clearance, minimize/expand, Arabic labels, and 44px targets. Honest loading / error / not_ready states; no dead transport block when clips are absent. Speed, repeat, and follow stay on the main player.

Grant / protected-answer logic is unchanged: page queues still omit `part === "result"`, manifests still request `?grant=`, and cue reveal still does not rewrite selected quiz answers.
